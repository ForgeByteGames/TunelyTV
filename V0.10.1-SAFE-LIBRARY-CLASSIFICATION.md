# TunelyTV v0.10.1 — Library classification and recoverable hiding

- A broad group label such as `Movies;Series`, a channel name (e.g. Pluto TV Action), or `tvg-id` alone no longer creates a TV-series episode. Only reliable episode patterns or explicit episode metadata classify as a series; ambiguous streams are treated as live.
- A single `.m3u8` stream is ambiguous: set the individual source to Movies in Account → Sources if it is a film.
- Exact duplicate M3U entries (same title and URL) are skipped in browser playlist interpretation. Invalid URLs are skipped by the existing parser; this does not mean a stream works.
- Users can hide unwanted or failing movie/episode entries from their library and restore them under Manage hidden library items. No playlist content or service credentials are deleted. Hidden item keys are SHA-256 URL digests, stored per user and source.
- A playback failure is **not** proof the channel is dead: temporary network issues, CORS, geo restrictions, codecs and provider limits can cause the same symptom. For this reason there is NO bulk auto-delete or unattended provider probing.
- Server-side user-scoped library-hidden table is created automatically in the existing database; no schema-breaking changes and no source deletion.
- Deployment: preserve your existing Railway volume and TUNELY_FERNET_KEY. Upload the package contents to the same repo.
