# TunelyTV v0.10.0 — Playlists vs. Where to Watch

## Approved user-facing meaning

* **Live TV**: channel guide for live streams in a user-authorized playlist.
* **Movies**: on-demand movie entries in the signed-in user's own authorized M3U sources.
* **TV Series**: on-demand series episodes from those sources, grouped by show title when marked with `S01E02`-style episode metadata.
* **Where to Watch**: separate streaming-service discovery (e.g., Prime Video, Netflix) using permissioned metadata, with official provider website links. It **does not** present paid movie streams or provider subscriptions as included with TunelyTV.

## Why a standalone .m3u8 appears as Live TV

A `.m3u8` is a media stream or HLS manifest, not inherently a movie or a TV channel. A single film stream such as the Sintel HLS demo cannot be reliably identified by extension alone. Its saved content type must be **Movies / VOD**.

## Fix the previously added Sintel test URL without readding it

1. Open `Account → Settings → Sources` (the Sources account page).
2. Find the saved **Sintel** source.
3. Change **Content type** to **Movies / VOD**. This updates the encrypted source config and preserves the source ID and saved URL.
4. Return to Home → **Movies**; the saved source is now listed as a movie.
5. Clicking the movie opens a private HLS/HTML video viewer (playback depends on HTTPS/CORS, allowed source, and supported codecs).

Use **Automatic** for mixed M3U playlists. On automatic, `S01E02`, `Series` or `Episodes` groups become series; VOD/films groups and `/movie/` entries become movies; ambiguous movie-themed live channels remain Live TV. If needed, override a whole source as Movies or TV Series. The source kind cannot automatically convert a protected/cross-origin stream into a playable video.

## Security, licensing, and limits

* No default channels, movie catalogs, or stream URLs bundled. No public exhibition of user library content; sign-in and existing server-side web-entitlement rules apply.
* Existing 1.x one-time license, trials, owner role, pairing, guide, favorites, and Railway database are retained.
* Source URLs remain encrypted at rest; the homepage obtains them only via authenticated, entitled API calls. Remote playlist contents are fetched by the signed-in browser only, subject to CORS, HTTPS/mixed-content and size bounds.
* Xtream remains unsupported in the browser. The first version supports provider M3U and standalone HLS URLs, not full VOD metadata APIs or offline downloads.
* Server and JavaScript do not scrape movie posters from the web. Playlist-supplied permitted HTTPS artwork only; no TMDb commercial rights are assumed. Leave TMDb integration disabled unless licensed for commercial usage.
* A source reclassified as Movies/Series will no longer appear as channels in the Live TV player. For a mixed playlist, use Automatic and clear movie/episode metadata for correct classification.
* Series grouping is based on playlist naming and may be imperfect. Episode metadata may vary by IPTV provider.
* Source fetch is limited to the 30 most recent non-Xtream sources for the public/home browser view for load control; user library is private. Optimize/paginate later for larger libraries.

## Deployment

Upload the extracted contents of the ZIP to the root of your **existing** `ForgeByteGames/TunelyTV` repository; do not create a new nested folder or upload secrets. Railway should rebuild the same service. Keep the existing `/app/instance` volume, database and **unchanged** `TUNELY_FERNET_KEY`. No database schema migration needed for the new per-source content type; it lives in the existing encrypted config.

Do not enable `TUNELY_METADATA_ENABLED` or `TUNELY_TMDB_RIGHTS_CONFIRMED` without actual rights. This build does not modify the existing backend licensing/trial rules.
