# TunelyTV v0.9.9 — M3U Plus Provider Setup (Private Testing)

**Status:** Packaged for review, not deployed to Railway. No real provider credentials or server requests were used in automated tests. No content or channels are bundled.

## What changed

- Account → Settings → Sources accepts a user-authorized M3U Plus `get.php` link (the ordinary M3U URL source option).
- Detects a *saved* link with `get.php`, `username`, `password` and `type=m3u_plus` without exposing the saved link in public source listings.
- Reads bounded playlist **metadata only**, on behalf of the authenticated, entitled account. Returns channel titles, categories, IDs, direct provider stream URLs, and secure `tvg-logo` values.
- Guide automatically attempts the *same provider's* conventional `xmltv.php` using the account's encrypted credentials. XMLTV may not be offered by every provider; missing/oversized guides fail with a helpful message, not fictional programming.
- Uses same-origin, owner-only metadata routes `/api/playlists/{id}/provider-channels` and `/api/playlists/{id}/provider-guide` for guide metadata on an HTTPS site (no browser CORS issue for these metadata routes).
- Uses the *existing* player/EPG, logo precedence, favorites, profiles, v0.9.6 licenses, and v0.9.8 optional rights-gated external-logo matcher. It does **not** restream live TV, proxy video, change a subscription, or attempt DRM/CORS bypasses for media.
- Saved playlists remain encrypted and available when the account is entitled. User-specific requests require a logged-in session and web-playback access; no anonymous upstream fetch endpoint.

## Safety and limits

- TunelyTV only uses the provider URL explicitly saved by an account and only recognizes the standard M3U Plus `get.php` form. Metadata fetches are bounded: 8 MB for playlists, 12 MB compressed/raw guide input and 22 MB decompressed guide output. A provider serving a larger guide will require a separate, scalable import/caching design.
- The server checks resolved addresses, refuses non-public IPs and local/internal hosts, connects to the checked IP, disables redirects, uses TLS certificate checks for HTTPS, and times out remote connections. It does not fetch arbitrary user URLs as a relay.
- **Prefer HTTPS providers**. HTTP transmits M3U Plus credentials and provider response in plaintext over the network. The new metadata reader accepts user-authorized HTTP for development but does not make it private or safe.
- **MPEG-TS / HTTP channels may be unplayable in browser**: secure web pages typically cannot open HTTP streams and browsers lack native MPEG-TS support. Ask the authorized provider for HTTPS HLS (`m3u8`) options when available. Playback is not automatically fixed by metadata import.
- Channel image rights are separate: use authorized provider logos and XMLTV artwork when allowed. Missing/insecure logo URLs fall back to initials. No third-party logos are shipped; external catalog matching stays off without rights.
- No provider password or stream URL should be placed in GitHub, screenshots, URLs sent to support, application logs or public marketing material. End users should not post M3U Plus links in chat. Rotate exposed provider credentials with the provider when possible.
- This update intentionally does not add direct browser Xtream credentials API playback. The existing Xtream account source is still separate.

## Install

1. In `ForgeByteGames/TunelyTV`, upload the **contents** of the ZIP at repository root (do not add a nested version folder). This is cumulative from v0.9.8. Do not delete existing repository content without checking it.
2. Keep your existing Railway service, mounted `/app/instance` volume, `TUNELY_DB=/app/instance/tunelytv.db`, and current `TUNELY_FERNET_KEY` **unchanged**. Never upload `.env`, real M3U provider links, SQLite files, or `instance/fernet.key` to GitHub.
3. Redeploy the **latest commit** and confirm healthy startup. The Dockerfile now includes `provider_metadata.py`.
4. Under Account → Settings → Sources, add an M3U URL if not already saved. Use your private `get.php?...&type=m3u_plus` provider link in the account settings only; do not paste it publicly.
5. Sign in with Owner testing privileges or a web-entitled account, open Watch Live, and choose the saved source. Wait for the channel list. The Guide will automatically attempt XMLTV from that same provider.
6. If the provider offers no working `xmltv.php`, use your own authorized HTTPS XMLTV URL or file through Guide setup. If browser playback fails, test a supported HTTPS HLS stream; don't expect this metadata feature to convert MPEG-TS video.

**Automated validation:** `python -m pytest -q` passed 60 tests using synthetic provider fixtures; JS syntax checks passed. Real provider availability, image rights, and browser codec support were NOT verified here.
