# TunelyTV v0.9.4 — automatic provider-supplied EPG

- When a user opens a saved **uploaded M3U file**, the authenticated `/api/playlists/{id}/playable` response also returns up to three provider-advertised XMLTV URLs parsed from the file's `#EXTM3U` header (`url-tvg`, `x-tvg-url`, `tvg-url`). The backend does not fetch guide URLs.
- When a user opens a **remote M3U URL** which allows browser CORS reading, the browser parses the same guide metadata. It does not guess endpoints.
- When importing a local M3U file for the current session, the guide link is detected without upload.
- The browser fetches the first compatible guide, attempts subsequent advertised alternatives on failure, parses real XMLTV programme metadata, matches channel `tvg-id`, `tvg-name` or display name, and refreshes hourly **while the browser is open and visible**.
- Raw gzip XMLTV supported in browsers providing `DecompressionStream`; compressed and uncompressed byte limits are enforced.
- A user-saved **manual guide URL wins** over automatic discovery. Removing the manual URL restores auto detection.
- The player shows accurate guide failure states, including missing embedded URL, blocked HTTPS/CORS, unsupported or inaccessible XMLTV. Never invent schedules.
- This release does **not** auto-discover guide URLs from Xtream credentials, because browser Xtream playback is not yet implemented; provider URL guessing is unsafe and unreliable. No central scraping, proxy, or included content.
- No server-side background refresh: an open, visible browser handles updates. Nothing runs when all clients are closed.
- No new environment variables, migration, or change to the Railway volume is necessary. Existing accounts, encrypted playlists, favorites, billing test state and TV pairing remain unchanged.
- Provider rights to XMLTV, compatible browser CORS/HTTPS, and valid guide metadata are necessary for actual listings.

## How to test on Railway
1. Update the existing GitHub repo; Railway redeploys the SAME service. Keep `TUNELY_FERNET_KEY`, signup code, and `/app/instance` storage volume unchanged.
2. Sign in and open an authorized saved M3U that advertises `#EXTM3U url-tvg="https://provider.example/guide.xml"` (the URL shown is illustrative, **not** a working guide).
3. Open TV Guide. A compatible, accessible XMLTV feed will populate listings automatically; no manual file is required.
4. If the guide does not appear, inspect the compact Guide status, then review your provider's advertised HTTPS/CORS/XMLTV compatibility. Advanced guide settings remain in Add a Source.
5. Verify playlist switching, saved manual-guide overrides, favorites, playback and Multi-View separately.

The automatic detection cannot recover a guide that isn't advertised by the provider. It cannot bypass CORS, provider restrictions, encryption, or unsupported formats. No channel subscriptions, guide service, or content are bundled.
