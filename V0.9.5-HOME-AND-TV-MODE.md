# TunelyTV v0.9.5 — Homepage and TV Mode Cleanup

This is a full replacement **source package for the existing Railway service**, based on v0.9.4. It is not a second project and is not yet deployed.

## Architecture / routes

| Address | Function |
| --- | --- |
| `/` | New **public discovery homepage** with compact landscape cards, dark navy and electric-blue interface, lightweight hero, live-TV category shortcuts, optional movie/series discovery, streaming-service availability filters, and pricing previews |
| `/watch` | Clean Live TV screen: player, immersive full-screen guide, Multi-View, and fullscreen only. Prior playback/guide logic is retained. |
| `/account` | Existing authenticated playlist/device/billing tools now reached through one horizontal navigation instead of the large sidebar. |
| `/account?section=sources` | Manage own M3U URL or file, authorized Xtream profile, and sources. Source upload is **not** a visible Watch TV action. |
| `/account?section=devices` | Device pairing, assignments and simulator management. |
| `/api/discover/...` | **Optional** server-side title metadata and actual provider availability through TMDb, disabled by default. |

When **stream.tunelytv.com** is eventually connected to this same service, that host's `/` redirects to `/watch`. The `tunelytv.com` host's `/` shows the public homepage. DNS is not changed by this package.

## UI design commitments

- **Original TunelyTV logo** retained. Main UI color family is dark navy, cyan blue, electric blue and royal blue; no bright green CTA styling.
- Home uses small **16:9 landscape** cards across multiple compact horizontal rows, matching the layout direction supplied by the project owner.
- Watch page no longer displays a setup tab, playlist-select sidebar, giant admin dashboard, many unnecessary player controls, or long page scroll. The underlying select and parser remain for last-source restoration; account settings remains the source editor.
- The **TV guide remains the central navigation**: compact program detail area at top, horizontally timed channels underneath, channel selection without scrolling down a webpage.
- The old Multi-View private-preview access issue and seven-day Plus trial enforcement are **not fixed** by this visual update.

## Movie and series discovery

The public site can pull *metadata only*, using operator credentials and appropriate usage rights. It never provides copyrighted media streams or streaming-service subscriptions. No movies/shows are included in this source package.

**Optional Railway environment variables (leave unset if not approved):**

- `TUNELY_METADATA_ENABLED=true` — explicitly enable external metadata requests after reviewing rights.
- `TUNELY_TMDB_READ_TOKEN=<secret>` — TMDb API read-access bearer token; **or** `TUNELY_TMDB_API_KEY=<secret>`. Keep secrets only in Railway Variables, never in GitHub or URL strings.

The app fetches metadata from the server, not directly from the browser. The API returns title search, films and series lists, and country-specific reported watch-provider names. The **Where to Watch** link opens the TMDb watch-provider page, not an unverified direct Netflix title URL. `Explore on Netflix` and similar service rows show provider-reported availability, **not official Netflix Top 10 rankings**.

**Licensing before commercial use:** Review TMDb's commercial data and imagery terms, its attribution and JustWatch requirements, and any third-party service logos. A free developer key does not, by itself, grant unrestricted commercial rights. If metadata is disabled, the production website shows honest, clean empty states rather than invented titles. The standalone preview deliberately uses fictional illustration titles and no actual availability claims.

## Deployment without losing data

1. Back up your Railway volume/database before the upgrade; do not delete or replace it.
2. Extract this ZIP; copy **the contents** into the existing `ForgeByteGames/TunelyTV` GitHub repository's root (not the ZIP itself). Make sure `discovery.py` and `site/home-v095.*` are included.
3. Keep the same Railway service and volume mounted at `/app/instance` with existing `TUNELY_DB`, `TUNELY_FERNET_KEY`, `TUNELY_SIGNUP_CODE` unchanged. Never commit secrets or local databases.
4. Railway redeploys from the GitHub commit. Confirm `/api/health` shows `0.9.5`.
5. Confirm `/` new public homepage, `/account` existing login/accounts, `/account?section=sources` upload forms, and `/watch` clean player/guide. Test last-selected playlist and Multi-View access separately.
6. After testing, set the domain records in the authoritative DNS provider. **Do not** point both domains to a new service or reset the database.
