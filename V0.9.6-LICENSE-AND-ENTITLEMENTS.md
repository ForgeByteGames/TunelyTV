# TunelyTV v0.9.6 — License & Entitlement Management

**PRIVATE TEST STAGING ONLY** — not live-payment ready; no channels or third-party subscriptions included.

## Implemented, server-authoritative

- `POST /api/license/trial/start` explicitly opts a user into **one** seven-consecutive-day Plus trial. No credit card, no Stripe call, no automatic charges. Unique user record, server timestamp, CSRF-protected.
- `GET /api/license/me` returns the user's effective plan, trial countdown/expiration, owned Plus major versions, web/mobile eligibility, TV slots, and Multi-View pane entitlement.
- Expiry is calculated against server time on every entitlement API check, playlist playback-config request and device sync; no cron or background task required. A viewing page also rechecks access once per minute while visible.
- After expiration the user falls back to Free (one registered TV, no web/phone/tablet playback), **without deleting saved playlists, favorites, account settings or devices**. Existing excess registered devices are retained but blocked from syncing until the account is eligible again or devices are removed.
- **Plus One-Time $19.99** grants designated features for major version **1.x** (initial commercial plan). License entries store major version, timestamp, and verified test payment event; licenses are preserved through subscription cancellation. Later major versions require their own version grant; this is a *license ledger*, not a commitment to host legacy web versions forever.
- Premium/Family subscriptions from existing **verified Stripe TEST webhook state** override Plus while active, returning to the owned Plus major version or eligible Free tier if the subscription ends. A recorded past subscription period end is also checked rather than trusting a stale `active` state indefinitely.
- TV profile and pairing claims check the provisional TV quotas (Free 1 / Plus 2 / Premium 3 / Family 5). These quotas require user approval before public sale; user-owned phone/tablet/browser sessions do not occupy these TV slots. Device access uses revocable app pairing tokens.
- `/api/playlists/{id}/playable` rejects web playlist configuration for ineligible accounts; the browser player also checks access and stops active in-app playback when an entitlement expires. This **does not secure or revoke a provider's external stream URL** once a user has retrieved it; provider authorization and concurrent-stream limits remain external.
- Multi-View access checks current account entitlements. Free 0, Plus or Plus trial 2 panes, Premium/Family 4 panes. **No global invitee-wide preview override remains**: the verified owner may test up to four panes separately from billing.
- Private verified owner role with `POST /api/owner/bootstrap` requiring a valid signed-in session, CSRF, `TUNELY_OWNER_EMAIL` matching that user, and a **separate strong** `TUNELY_ADMIN_SETUP_TOKEN` env secret. Only the first verified owner may claim; the owner role is stored in the database. Remove the setup token after claiming.
- The Account app shows an owner-only, read-only **Owner · Licenses** view with users' plans, trials, version licenses, and audit log (max 100 results). No owner endpoint can silently charge cards, change a Stripe subscription, or grant arbitrary permanent licenses.
- Existing verified Stripe TEST purchases from v0.8+ can be migrated into v1 one-time license records when upgraded. Test-mode purchases with a known Stripe payment intent can be revoked after a signed full refund event. Real checkout remains disabled.

## Railway upgrade — use SAME existing project

1. Download ZIP, **extract** and update the existing private `ForgeByteGames/TunelyTV` repo source files. Do not upload a second copy in a subfolder. Confirm root contains `Dockerfile`, `server.py`, `billing.py`, new `licensing.py`, `site/`, and `tests/`.
2. Railway uses the existing service and the existing mounted volume at **`/app/instance`**. **Do not delete/replace the volume or change `TUNELY_FERNET_KEY`**; license tables are added to the existing SQLite file on app startup. Back up existing SQLite database and encryption key securely first.
3. Keep `TUNELY_ENV=production`, `TUNELY_SIGNUP_CODE`, `TUNELY_DB=/app/instance/tunelytv.db`, and `TUNELY_FERNET_KEY` as already configured. The obsolete `TUNELY_MULTIVIEW_PRIVATE_PREVIEW` variable can be removed; it no longer grants any user free access.
4. Optional **verified owner setup** (recommended so the owner can test everything): add Railway Variables `TUNELY_OWNER_EMAIL` set to your **already registered account email** and `TUNELY_ADMIN_SETUP_TOKEN` set to a distinct secure random token with at least 24 characters. Don't reveal either value in a screenshot or chat. Visit `/account?section=billing`, sign in to that same email account, and submit the owner token in the **Verify your TunelyTV owner account** panel. A successful claim exposes the **Owner · Licenses** sidebar item. Remove `TUNELY_ADMIN_SETUP_TOKEN` from Railway and redeploy to close setup. Your user role persists in the volume.
5. Open `/api/health` and confirm version `0.9.6`. In Account > Plan & Billing, eligible testers can click **Start my 7-day trial**; no card or purchase necessary. Existing owner can also test Multi-View without using the trial.
6. Validate one trial, no duplicate activation, web playback access, Multi-View, registered-TV quota, and account data preservation through one Railway redeploy. Use only authorized sample streaming sources.

If the owner has already claimed a role, additional claims are rejected. The bootstrap email alone **never** grants Owner access. Bootstrap never generates a master password or bypasses login.

## Not implemented / not safe for paid public launch

- Stripe LIVE purchases and recurring billing are **disabled**, and yearly pricing/intervals have not been integrated or finalized. Only signed, configured Stripe **test-mode** webhooks can create a purchased Plus version grant.
- Full production payment reconciliation, chargeback/dispute workflows, failed-payment grace periods, refunds across all stores, Apple/Google in-app purchases and receipt verification, tax, and customer-initiated major-version upgrade checkout still require implementation.
- Final terms for the one-time version license, duration of support/security fixes, and any paid upgrades or ongoing hosted features must be published before selling.
- Free native TV app is not released. TV/phone/tablet native apps need to consume and enforce the entitlement API. Web browser restrictions cannot control external content-provider playback beyond TunelyTV's own app.
- Stronger authentication and account recovery, email verification, audit/log retention, rate limits distributed across instances, backups/restore drills, privacy/security review and legal/commercial API permissions remain required.
- DVR, catch-up and Tunely Home remain **unbuilt / subject to recording-rights review**. Multi-View remains a private player prototype and provider concurrency/codec compatibility may prevent multiple panes from playing.
- SQLite requires a **single Railway replica and one worker**. Multiple instances or migration to PostgreSQL need a separately reviewed transactional design.

**Important:** This private-development release is not an invitation to start selling subscriptions. Users' purchases and licenses are not considered live, and the legal Terms/Privacy and storefront must be aligned before public paid launch.
