# TunelyTV v0.9.8 — Automatic missing-channel-logo matching

## What's included

- Fixes CSP that mistakenly blocked playlist/XMLTV HTTPS logos: `img-src 'self' data: https:`. Images load directly in the browser, with no provider stream proxy or hosted logo library.
- Keeps priorities: playlist's `tvg-logo`, XMLTV channel icon, then a rights-approved external directory match, then text initials.
- An optional **on-load automatic lookup** for channels missing M3U icons. It sends **only TVG IDs and channel display names to TunelyTV's own authenticated backend**, never playlist URLs, stream URLs or credentials.
- Supports exact IPTV-org channel IDs and unique exact names, rejects ambiguous name matches, does not apply fuzzy guesses. Public directory lists are cached for 24 hours per app process; user can refresh the current playlist via **Live TV → Guide → Guide setup → Refresh missing logos**.
- Catalog images are linked in the browser, never downloaded or mirrored by TunelyTV. Unavailable logos fall back to initials. Unmatched or regionally ambiguous channels are not assigned guessed logos.
- Includes rate limiting, 2,000-name request limit, HTTPS-only logo URL sanitization, signed-in/entitlement/CSRF checks, request timeout and maximum download bytes. Requests to the directory are server-initiated from fixed URLs, not from user-supplied endpoints.

## Usage and rights

**The external directory is disabled by default.** The [IPTV-org API](https://github.com/iptv-org/api) publishes channel and logo-link metadata; its unlicensed/Unlicense directory data does **not** automatically grant rights to third-party broadcaster artwork. Some images are owned by television stations and may be protected by copyright or trademark. Do not enable directory matching in a commercial/public TunelyTV deployment without independently validating the applicable image rights and obtaining required permissions. Merely setting an environment flag does not provide permission.

These flags must both be true **after appropriate permission is secured**:

```env
TUNELY_LOGO_AUTOMATCH_ENABLED=true
TUNELY_EXTERNAL_LOGOS_RIGHTS_CONFIRMED=true
```

For now leave both **unset or false**. This allows the earlier provider-supplied `tvg-logo` and XMLTV icons to work, with no reliance on the community directory. The external image lookup is an optional future enhancement; it does **not** add streams or EPG listings.

## Limitations

- Directory matching has been tested with simulated catalog responses, **not** with the user's private 1,481-channel playlist or a live rights-cleared directory.
- International and branded versions of stations can be ambiguous. Only high-confidence exact matches are returned. Directory images can disappear or be blocked by the image host. Their trademark permissions are not asserted by the software.
- No attempt to scrape Google Images, search-engine results, licensed artwork, or generate fake logos.
- No automatic background job runs when the Railway service is idle; on-load lookups are automatic for approved deployments, with a 24-hour catalog cache.

## Deploy

Upload the **contents** of this ZIP into the existing GitHub repository root, preserving the Railway service and `/app/instance` database volume. Do not change `TUNELY_FERNET_KEY` or upload `.env`, database files, private playlists, or secrets. New module `logo_catalog.py` is included in Dockerfile. All existing license/billing features remain.
